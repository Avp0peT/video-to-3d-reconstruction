# 通用物体区域增强

本流程不按物体名称、手套部位或固定帧号分支。输入是**已绑定的完整视频图像与掩膜时间轴**、已有 SfM 数据库，以及初次区域跟踪/重建记录。它扩展可用观察，不承诺所有物体都可完整重建。

## 新对象入口

使用项目 Python 执行 `scripts/run_photo_demo.py reconstruct-regions --mask-run <完整融合掩膜目录> --sfm-run <原生SfM目录> --baseline-report <原建模目录> --output <新目录>`。

初次区域重建完成且有模型时，默认自动执行反向补充和至多一轮中间帧桥接；无需手动指定补帧编号。`--no-refine` 只做初次区域重建，`--prepare-only` 只生成计划。掩膜仍由既有 `propagate-masks --full-video` / `fuse-masks` 路径生成，不用空白掩膜填补未知结果。

已有区域重建使用：

```powershell
& '<项目Python绝对路径>' -B -X utf8 '<仓库>/scripts/run_photo_demo.py' refine-object `
  --run '<已完成区域重建目录>' --output '<新的增强目录>'
```

默认执行；加 `--prepare-only` 后可用 `execute-object-refinement --run <增强目录>` 执行冻结计划。一个目录只尝试一次，失败记录保留，不自动改阈值或重试。有且仅有一个 `geometry/RESULT.json` 或 `geometry02/RESULT.json` 时自动选择；有多个结果时要求显式 `--source-geometry geometry02` 等，不猜最新结果。

## 自动选择规则

1. 保留原始图像、掩膜、SIFT 对应和已提交前向轨迹；独立反向轨迹只是新增候选。
2. 根据当前相机域有效分量，优先检查跨分量邻接区间，也检查同一分量包围未注册端点的区间。
3. 对选中区间，在实际存在的中间帧中选择最接近三分位置的帧。完整时间戳可用时按时间选，否则按解码索引选，不生成插值图像。
4. 补入实际数据库图像/rig/frame 关联；mapper 请求名单必须恰好覆盖冻结输入。
5. 分别报告原始端点、新增端点、各独立分量、拒绝原因、来源哈希和回收状态。没有可选帧不等于物体已完整。

`object-region-bridge-policy-v1` 默认最多新增 24 帧，总计最多 96 帧；初次区域输入仍限 2–64 端点。它们是资源限制，不是精度标准。旧 `glove-*` 数据契约和 `original64_*` 报告字段保留兼容，算法不据这些名字判断物体类别；新通用统计使用 `original_endpoint_*`。

## 当前边界

- 视频区域增强要求完整、同尺寸、有来源绑定的时间轴；零散照片继续使用照片建模路径。本增强不会把照片强行当连续视频。
- 缺失掩膜、来源漂移、相机域失败、原生失败保留为明确状态，不放宽几何检查来凑完整物体。
- 无已绑定部位标注时，背面/手指等部位覆盖率为 `null / NOT_EVALUATED`，不使用案例帧号猜部位。
- 区域跟踪仍使用既有局部纹理/前后向/掩膜约束。未新增 LoFTR、非刚体求解器、材质分类器或轮廓重建。
- 稀疏重建完成不等于稠密表面、Blender 外形、CAD 实体或尺度验收。透明、镜面、无纹理、严重形变等情况可能需要不同的证据或模型。

所有真实重建限 CPU 两线程，各阶段沿用独立进程树看守和内存/时间预算，原始产物保持只读。新类别端到端效果仍需实际数据验证。
