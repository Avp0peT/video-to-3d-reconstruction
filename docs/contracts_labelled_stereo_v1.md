## 2. 输入契约

1. `first`、`second`：`Mapping[str, tuple[有理数, 有理数]]`，**标签集合完全相同**。
2. 标签数 `n ∈ [4, 32]`。`n > 32` 明确拒绝（不声称支持）。
3. 四个锚标签 `a, b, c, e` 必须存在且两两互异。
4. 每幅图中**坐标不得重复**（保证两个投影在该点集上单射）。
5. 有理数：接受 `int`（`bool` 除外）与 `fractions.Fraction`。
   `bool`、`float`、非有限值、非数值类型一律**明确拒绝**；`|分子| ≤ 10^12`、分母 `≤ 10^12`。
   **不做任何静默量化**——`float` 不会被转成近似分数。
6. 两幅图的 `abc` 都必须是非共线三角形。
7. **相容性**（原文前提）：在 `abc → (0,0),(1,0),(0,1)` 归一化后，
   对每个标签 `i` 都必须存在标量 `t_i` 使 `q_i − p_i = t_i · v`（`v = q_e − p_e`）。
   任一标签不满足 → 该对应不可能来自同一三维体的两个平行投影，明确拒绝。

**原子性**：`prepare_views` 只在**同一标签集合**上有定义；两个投影必须分别单射。
指向同一三维体的**逐点对应是否给定**由输入承担——四个锚点通过**不**自动认证其余匹配。

## 3. 输出契约

`ConstructionResult`：

| 字段 | 含义 |
|---|---|
| `status` | 见下表 |
| `points` | `label → 精确坐标`（AlgT′ 为三元组，AlgS₀ 为二元组）；**每个输入标签都保留**，即使两个标签输出重合 |
| `witnesses` | `label → PointWitness(branch, route, source_view, detail, completeness)` |
| `anchors_out` | 锚点的输出位置 |
| `v`, `t` | 记录的方向与该归一化下的相容标量 |
| `unsupported` | 声明为 UNSUPPORTED 的标签（分支 Gate 未通过） |
| `failure_reason` | 拒绝 / 失败 / 预算耗尽的原因 |

状态（R2 修订：三类失败必须分开表达）：

* `OK` —— 全部标签构造成功；
* `NOT_OFF_PLANE_PREREQUISITE_UNMET` —— `v = 0`：两幅已标记图像仿射等价（`e` 落在 `abc` 平面）。
  **不**报告已恢复体，**不**自动换锚点隐藏失败；
* `BUDGET_EXCEEDED` —— 精确运算预算耗尽：未完成标签列在 `unsupported`，**不**记成"不存在"或"错误匹配"；
* `UNSUPPORTED_BRANCH` —— 输入**合法**，但某标签的分支前提不满足或本实现无法正确落地
  （逐条给出原因）；该标签 `completeness = "UNSUPPORTED"`，**gate 不通过**；
* `INVALID_INPUT` / `INCOMPATIBLE_CORRESPONDENCE` —— **不**作为构造返回值，而是由
  `prepare_views` 抛 `ValidationError(kind=...)`：
  - `kind = "INVALID_INPUT"`：标签集合/标签存在性/取值类型（bool、float、非有限、超限）、
    坐标重复、`abc` 退化等**输入格式或标签**问题；
  - `kind = "INCOMPATIBLE_CORRESPONDENCE"`：输入格式合法，但该对应不可能来自同一三维体的
    两个平行投影（不相容）。
  内部构造失败**绝不**概括为"输入非法"：它按标签记 `UNSUPPORTED`，整体为 `UNSUPPORTED_BRANCH`。
  `failure_reason` 会显式写明 `INTERNAL_CONSTRUCTION_FAILURE (not an input-validity rejection)`。

## 4. 记录的初始选择（原文 p333 允许的自由度）

辅助方向取**竖直**；把第一幅图的 `abc` 放到 `z = 0`、`e` 放到 `z = 1`。
标签 `i` 的代表点记为 `(u_i, t_i)`，其中 `u_i` 是第一图坐标在 `abc → (0,0),(1,0),(0,1)`
归一化后的值。**这是被记录的规范化选择，不是恢复出的度量位姿。**
见证中标记为 `INITIALIZATION_RECORDED_CHOICE`。

## 6. SOURCE-DERIVED 补足（明确标记：非原文逐字规定）

1. **U1（交线上的逐点对应）**。只把交线当集合映射会留下一个自由度。
   实现取交线上**两个不同的基点**，其对应由 `abc` 映射诱导并**保留同一参数**，再加上
   `e` 的对应，从而确定目标平面映射。见证记录基点与参数；换基点/参数结果不变（有测试）。
2. **U2（AlgS₀ 目标面退化）**。输出 `e0` 可落在 `L0` 上，`c0d0e0` 可共线。
   允许**秩降低**的仿射映射，不强制中途可逆，标签重合**不合并**。
3. **引理 6 情形 4 的精确可解形式**。当 `de` 的两幅像平行/重合时，"两条 `de` 的交点"没有唯一解。
   实现用**面映射在 `de` 像上的不动点**（数学上等价于 `x = de ∩ abc 平面`：若
   `x = p_d + λ(p_e − p_d)` 且 `λ = t_d/(t_d − t_e)`，则 `F(x) = x`），并在 `de` 无法定值时按
   原文"对称换名"改用局部辅助边 `aux`（原始面为 `ab`）。已在见证中记录所用方法（`second_point_method`）。
4. **`abc` 归一化后的同一性**。两幅图在 `abc` 平面上因三点对齐而一致，故交线的两幅像在归一化
   坐标下是同一条线；引理 6 情形 1 的"传递"在本框架中即恒等映射。
5. **角色代入（ROLE SUBSTITUTION）**。引理 6 的措辞针对三角形 `(a,b,c)` 与面 `(c,d,e)`，因此把
   `a`、`b` 写成三角形的两个自由顶点。步骤 2б 把面换名为 `aed` / `bed` 后，**共享顶点不再是 `c`**，
   自由顶点也随之改变；引理 6 情形 2/3/4 所用的辅助边必须由**该面局部的已知顶点**推出
   （`aux = (a,b,c) \ {面已知顶点}`），否则第二交点会等于已知点（R1 缺陷，见 §8）。
   情形 3（平行边）的前提也必须按**前提**判定，不能只看"两幅像平行"：
   * `de ∥ 平面(abc)` ⟺ `t_d == t_e`（`t` 为记录高度，可由图像精确算出）；
   * `aux ∥ 平面(面)` ⟺ 面映射 `F` 固定"虚拟点 `面已知顶点 + aux 方向`"的像。
     该虚拟点在 `abc` 平面内，故两幅像重合；"它落在面平面上"恰是原文的四点谓词，即
     `F(像) == 像`。（R2 反例：`de` 与 `ac` 的两幅像平行，但 `de ∦ 平面(abc)`，只按像平行
     会取错交线方向。）
6. **`de` 两幅像平行/重合时的补足**（＝上条情形 4 的兜底）：沿用同一不动点机制，只是改在 `aux`
   边上取不动点；见证里 `second_point_method` 记为 `aux_edge_fixed_point(<aux>)`，
   `de_intersection` / `de_coincident_fixed_point` 分别表示直接交点与 `de` 边不动点。
7. **U1 基线退化在可达域内不可达（带前提的证明）**。`U1` 需要"交线上两个基点 + `e` 的对应"。
   若 `e` 在**源视图**下的像落在 `L` 的像上，该补足失效。在 `STEP2` 分支中这不可能：
   * 前提 P1：`abc` 在**两幅图**中都是三角形 ⟹ 每个投影在 `abc` 平面上单射，并把
     `L = 平面(abc) ∩ 平面(面)` 双射地映成其像；
   * 前提 P2：所用**源视图**中 `(面已知顶点, d, e)` 是三角形（实现里源视图必取三角形的那一幅）。
   * 全局前提：`e` 在 `abc` 面外，因此 `e ∉ L`；下述 `e − y` 非零。
   反设 `e` 在源视图的像落在 `L` 的像上。则存在 `y ∈ L` 与 `e` 同像，故体方向 `e − y` 平行于该
   投影方向；而 `y`（在 `L` 内）与 `e` 都在面平面内，于是该方向落在面平面的方向空间里，即面平面
   平行于源投影方向——那么源视图里 `面已知顶点, d, e` 三点共线，与 P2 矛盾。∎
   实现保留该守卫作为防御性断言；它**不**计入已覆盖的来源分支。
8. **三维面不保证投影成三角形**：面（三点不共线）在投影方向平行于该面时会退化为一条线。
   因此 `aed` 一条路不可用（三维退化或投影退化）**不等于**输入非法；此时实现按
   步骤 2б 继续走 `bed`，`STEP2B_REDUCE_FACE_BED` 是**可达的成功分支**（有 3D 真值断言）。
   这与"U1 基线退化不可达"是两件独立的事：前者可达，后者在 P1/P2 下不可达。

## 7. Gate

**分支完成**的定义：该分支被**真实执行**，并且其输出坐标被断言**等于独立真值**（三维真值或明确
的标记载荷仿射映射 ＋ 两投影重建）。"预期返回 UNSUPPORTED 的用例通过"**不算**分支完成。
未触达的分支不得计入覆盖。

**required_branch_gate 通过的充分条件**：两个算法 + 引理 6 全部必需分支（含 `A`/`B`/换名三种共同点
与 `BED` 归约）+ `U1`/`U2` 均在**最终字节**上被执行且以真值断言通过；`U1` 基线退化按 §6.7 的
前提证明为不可达（作为防御守卫，不计分支）。任何未修正确的合法分支必须记 `UNSUPPORTED` 且 gate
不通过，**不得**通过放宽输入规则掩盖。

本轮 Gate 结论见 `outputs/delegation/LABELLED_STEREO_C/<run>/RESULT.json`。

主线补充验收入口：`outputs/delegation/LABELLED_STEREO_C_MAIN/20261008_r2_closure/HANDOFF.md`。
它补测换名共同点：真值 `e=(1/4,3/2,1), d=(1,3,2)`，两图为 `(x,y)`、
`(x+z,y+2z)`。`cde` 两图共线而体中不共线，换到 `aed` 后局部共同点为 `b`，
交线为 `ab`；给定 `A=(0,0), B=(1,0), C=(0,1), E=(2,1)` 时 `d0=(9/2,2)`。
此例纳入必需分支集合，同时验证两公开算法的精确坐标、局部角色和两输入重投影。
实际通过状态以该入口保存的 JUnit/RESULT 为准；有限用例不构成所有合法输入的形式证明。
本轮新执行记录不修补或替代 R1/R2 历史入口的缺失记录。
即便两个算法与引理 6 全部分支通过，本契约也**不**据此声称照片重建、研究线或定理 6 完成。
