# 已有视频的光照稳健跟踪对照

这是自动续跑入口：复用已完成的短中断恢复结果，核对原输入、全部解码帧、SAM mask、控制代码和 OpenCV 字节，执行新跟踪、原生几何消费及三方报告。

```powershell
& '<原生Python>' -B -X utf8 scripts/compensate_object_tracks.py run --control '<recover_object_tracks已完成目录>' --output '<全新结果目录>'
```

当前方法是局部光度**预归一化**，不是联合求解运动与亮度参数，也不是 Kozlov 原书的算法。31像素窗口估计均值和对比度，归一化图仅供金字塔 LK 和前后向检查；原图上的15像素块再检验 ZNCC、正亮度增益、偏置、拟合残差、纹理和饱和比例。候选检测、SAM边界和轨迹恢复继续使用原图；恢复沿用原有双向相关、歧义与邻居几何检查，新光度门只作用于连续跟踪步骤。

种子配额、采样索引、短暂缺失上限、原生两视图验证和建模参数保持原值。只在真实 SAM 有效的采样帧保存实测点；NO_MATCH仍清空；没有预测坐标插值或补造mask。恢复身份仍是候选对应，不是物理真值。

报告比较分区连续跟踪（辅助）、短中断恢复（主要）和本轮光照稳健方案。每帧展示初始候选、至少三个真实采样支持、独立原生分量中的点，另列4/8/12格占用率。占格率不是物体表面覆盖率，不拼接不同坐标系的模型。用户可在报告逐帧检查点的位置。

`steps.jsonl`还记录同一个新方案当前活跃点集上的旧原始灰度步骤与新步骤结果。此诊断不更新旧轨迹，因此不等于完整重跑旧方案。`photometric_only`为新步骤接受而旧步骤拒绝的次数，发生在采样mask过滤之前；`photometric_history`表示此ID此前至少发生一次该事件，`photometric_only_this_decode`才表示本原始帧发生。它们不是新增三维点数，也不证明失败由光照造成。

预算：CPU两线程、跟踪630秒外层/600秒内层、原生240秒、进程树提交量8 GiB、输出1 GiB；独立新目录，失败或无法确认回收则停止，不自动调阈值重试。无需重新解码、SAM推理、安装或GPU。此入口可以重复用于同类已完成产物，尚未改为公共建模入口的默认策略。

## 依据与边界

- 本地《Сборка макета》书稿印刷61–62页（PDF55–56）允许ε近似并复核整体编码关系；这是几何点集对应，不是像素光照模型。
- [OpenCV光流文档](https://docs.opencv.org/4.12.0/d4/dee/tutorial_optical_flow.html)解释亮度恒定假设。
- [ECC配准研究](https://doi.org/10.1109/TPAMI.2008.113)提供光度稳健区域对齐依据；本实现没有调用ECC，也不声称复现该论文。
- [Brox等光流研究](https://lmbweb.informatik.uni-freiburg.de/Publications/2004/Bro04a/)结合亮度和梯度约束；本轮未实现该完整方法。

已知限制：周期纹理可以让局部新旧跟踪都接受整周期的错误位移。无纹理、遮挡、饱和及移动高光不能仅靠归一化解决；合成亮度测试通过不代表真实视频几何正确。无光照变化时该预处理也会改变结果，因此真实运行收益不能全部归因于曝光补偿。
