## Q1 — 2002 与 2025 的 `остов` 如何共存？【`RESOLVED_DESIGN` / `IMPLEMENTATION_PENDING`】

- **原定义**：S-2002 的 `остов` 是 r-覆盖集合中点数最少的代表；S-2025 PDF p.10 / 期刊 155 的
  `m-остов` 是独立覆盖块的中心集合。S-2025 p.5–6 的叙述另有非正式描述，不能取代 p.10 正式定义。
- **原问题**：同名不代表同义；直接共用实现会丢失来源及语义边界。
- **裁决 P4**：按来源和语义隔离，新增类型可用 `Ostov2025M`；保留现有公开 API，
  不为名称统一大规模重命名 `compression/official/kozlov_sketch.py` 等旧模块。
- **后续验证**：分别按定义检查输出、输入条件和来源标注。某些输入偶然得到相同点集，不能证明两定义等价；
  命名或导入扫描只能防部分架构回归，不能证明数学语义正确或完全没有重复算法。

## Q2 — `эталон` 集合与单个 prototype【`RESOLVED_DESIGN` / `IMPLEMENTATION_PENDING`】

- **原定义**：S-2025 PDF p.12 / 期刊 157 将群组中满足 M-футляр 容纳全组条件的图像称为其
  `эталоны`，并明确使用 `набором эталонов`，因此结果是集合，可有多个。
- **原问题**：brief 的单个 `E ∈ G` 无法完整表达该集合；任意选一个还需要额外规则。
- **裁决 P5**：严格层输出满足条件的集合。工程/UI 若需一个代表，另设 `selected_prototype` 和选择规则。
  搜索不完整时只返回候选集及 `complete=false`，不得称已找到全部 эталон。
- **后续验证**：使用已知可审计的小例检查集合内容与完备性；即使有限样本中从未发现多个结果，
  也不能把集合定义简化为单元素。依赖严格 fits 的结果尚不能宣称理论正确。

## Q3 — 最小面积外接椭圆的算法与依赖【`TESTED_REAL_PARTIAL`；数值有限点域与真实特征点单例已测试】

- **原定义**：S-2025 PDF p.4 / 期刊 149 以包含凸包 W(X) 的唯一最小面积椭圆定义中心与长轴尺寸；
  共线退化为线段，中点为中心。文中引用 [5] Загускин，УМН 13:6 (1958) 89–93。
- **已实现数值范围（2026-10-07）**：[契约 `ellipse-area-v1`](contracts_ellipse_v1.md) 冻结了 1–4096 个有限二维
  binary64 兼容点、精确去重/仿射秩、点/线退化、Khachiyan 对偶更新、迭代/work 上限与明确失败语义。
  [`minimum_enclosing_ellipse`](../src/kozlov_lab/kozlov2025/ellipse.py) 用 NumPy float64 求候选，用 `Fraction`
  在实际世界坐标上精确验证包含性和面积上下界；近共线但精确秩 2 的输入不能悄悄压成线段，数值条件差时可失败。
- **已证明的输出语义**：只有精确包含且面积比不超过 `1 + area_tolerance` 才返回 `APPROXIMATE_CERTIFIED`。
  该保证只针对实际存储的 binary64 输入；不是精确 Kozlov 中心，没有中心坐标误差界或长轴尺寸误差界，
  更不能证明物体/图像测量精度。`MAX_ITERATIONS` / `NUMERICAL_FAILURE` 不升级为严格 fits、覆盖或形象结论。
- **裁决 P2 / T04 边界**：先形式化与实现椭圆单模块。可用现有 NumPy；SciPy 是按需启用的可选依赖，
  在项目隔离环境安装并锁定实测版本，不改系统 Python。OpenCV 的 `fitEllipse` 不是该问题的替代算法。
  不强制所有椭圆运算采用精确 `Fraction`；合理的数值方案须明确精度和失败语义。
- **已有验收**：[pure02.xml](../outputs/delegation/ELLIPSE_2025/20261007T105441Z_main/pure02.xml) 保存 45 例全部通过
  （0 failure、0 error、0 skipped）：包含性、已知解中心/面积、仿射中心/形状/面积协变、点/线/重复/近线输入、
  预算耗尽、非法输入、不可变结果和独立重算证书。中心协变性单项不足，因为质心也满足它；有限测试不是一般性定理证明。
- **真实单例证据**：[demo01 结果](../outputs/delegation/ELLIPSE_2025/20261007T105441Z_main/DEMO_RESULT.json)
  记录 image 4 `images/000003.png` 的全部 3571 个特征像素，仅精确去重为 3179 点；395 次更新后返回
  `APPROXIMATE_CERTIFIED`，独立 Fraction 重算确认全部原始点包含与面积比上界 `1.0049380785009892 ≤ 1.01`。
  一次调用退出码 0，输入来源未改；该单例只使数值模块达到 `TESTED_REAL_PARTIAL`。
- **仍未完成与应用边界**：上述点集不是物体 mask、图像边界或背景移除结果，真实物体中心/尺寸精度未评估。
  精确原文中心、中心/尺寸误差保证及依赖它们的严格高层结论不能由当前面积证书替代，RC04 不登记为全项完成。
  API、各状态及证书说明见 [ELLIPSE_USAGE.md](ELLIPSE_USAGE.md)。
- **无关阻塞已解除**：Pillow + NumPy 足以启动照片 IO，不能把 SciPy/OpenCV 尚未安装当作全部 T01 的阻塞。

## Q4 — `футляр` 的半径及完整构造条件【定义边界已定；退化/边界 `OPEN`】

- **primary 原定义（S-2025 PDF p.10 / 期刊 155）**：独立块 `A₁,…,A_m` 覆盖 A，块中心组成 O；
  `R = min_{i≠j} ‖o_i−o_j‖`。每个块中的点须距所属中心比其他中心更近；块须位于对应的圆域，
  圆域重叠时使用相应截断区域。原文称 `R < size(P_A)/2` 时覆盖不正确。
- **不能逆推充分性**：`R ≥ size(P_A)/2` 不能代替独立性、全覆盖、区域包含和最近中心归属检查。
  原登记中将其写成完整的 `правильное ⟺ ...` 已撤回。
- **generalized 原定义（PDF p.13 / 期刊 158）**：O 和互位给定，另给 `r ≤ min_{i≠j} ‖o_i−o_j‖`。
  每个点有唯一最近中心，点到该中心的距离 **`< r`**；每点归入一个块，且全部块非空。
  半径上界的 `≤` 与点距条件的 `<` 不同，不得混成一套开/闭圆判断。
- **裁决 P6**：按各自正式定义实现。primary 的 R 固定；generalized 的 r 是原文允许的受约束输入，
  不是任意自由区域。当前不扩展额外可调区域或椭圆替代对象。
- **仍未决**：m=1 的最小点距、重复中心（包括中心构造可能重合）、primary 圆域边界相等，
  以及严格不等式的数值容差处理。不能擅自填默认值、将相等强判接受或把数值不确定当作数学 False。
- **后续验证**：分别检查两版完整条件；构造半径筛查通过但覆盖/归属/截断条件失败的反例；
  将未决边界显式报告。不能只测试一个 `R < size/2` 拒绝例就宣称实现正确。

## Q5 — `S⋆` 的适用规模与搜索完备性【`OPEN`】

- **原定义**：S-2025 PDF p.3 / 期刊 148，`S′ = P(S) \ {∅}`，`S⋆ = P(S′)`，
  因而 `|S⋆| = 2^(2^N−1)`。N=4 时为 32768；随着 N 增长，完整枚举很快失去工程可行性。
- **原问题**：不得将有限、但巨大的搜索空间说成数学上不可计算，也不能默认真实图像可全枚举。
- **待定工程范围**：很小的环境可作枚举 oracle；一般输入可探索候选群组判定或有界搜索。
  须记录搜索域、预算、停止原因与完备性；只检验部分候选不能证明完整群或全部 эталон。
- **后续验证**：先确定一个可处理规模，在相同搜索域内核对枚举与判定器，再讨论扩大规模。
  T00-R 不运行该实验，也不放行全部理论模块。

## Q6 — 严格 `fits` 的最优互位与稳定性【严格求解 `OPEN`；接口边界 `RESOLVED_DESIGN`】

- **原定义**：S-2025 PDF p.9–10 / 期刊 154–155 定义 ε 邻域、ε-аффинные 变换及
  `l_A(B′) = max_i |a_i b′_{ψ(i)}|`，其 `искомое` 互位带邻域最小性与稳定性要求。
  有限求解程序所用定理引用 2007 教材 [1]，目前全文登记为 `SOURCE_REQUIRED`。
- **未决问题**：如何证明或判定稳定性仍未解决；现有 `stereo/correspondence._pair_cost`
  的重投影平方和是不同准则。数值最小值不能自行替代该定义。
- **裁决 P7**：严格 API 保留稳定性要求，无法证明时返回 `UNKNOWN` / `UNSUPPORTED` 及原因。
  数值失败不等于数学 False。近似优化必须另名并标 `ENGINEERING_INTERPRETATION`。
  其结果不得传递成严格 granularity、полная группа、эталон 或完整理论正确性已验证。
- **后续核对**：取得教材并提取适用定理；按原文形式化量词和前提，再选择求解方法。
  多个数值并列最优可作诊断案例，但仅靠样例不能裁定稳定性定义。
  教材缺失阻塞严格求解器，不阻塞其他已定义模块或照片 IO。

## Q7 — S-2025 的三维范围与本项目新增定义【范围 `RESOLVED_DESIGN`；实现待做】

- **原文范围**：S-2025 PDF p.2 / 期刊 147 明文提及 R³ 中的三维图像、动态世界的四维表示与高维推广，
  随后说明后文讨论二维图像。不能再称“纯二维”或完全不可引用于三维背景。
- **工程边界**：本文详细展开二维结构；未给出本项目完整三维实现及真实照片重建流程。
  可以引用明确写出的范围陈述；项目具体新增定义、算法与验证标 `OUR_3D_EXTENSION`。
- **引用前提**：S-1996 的三维/投影结论须逐条核对模型和定理前提，不能整体为现代 SfM 背书。
  词频不能证明三维来源唯一、术语不存在或两篇互不相关。
- **后续验证**：先完成相关二维契约与验证，再审查拟议三维定义与共面特例的一致性；
  不预设所有三维结果都已经由原文或二维数值测试证明。

## Q9 — 2002 与 2025 的 `дробность` 是否相同？【`OPEN`】

- **检索线索**：历史统计在 S-2002 抽文中匹配词干 `дробност` 1 次，在 S-2025 中 11 次；
  后者 PDF p.12 以 m-совместимость 的最大 m 定义粒度。计数只作定位，不能证明概念首次或唯一出现。
- **未决问题**：S-2002 的相关上下文尚未逐条完成语义对照；不得提前合并实现。
- **后续工作**：核对完整段落、定义依赖和前提，记录是否能建立对应关系；不能只靠同名或样例相等判定。

## Q10 — `признак` / `метка` 的输出关系【schema `OPEN`】

- **原定义**：S-2025 PDF p.16 / 期刊 161，признак 是最小的 существенная часть，
  метка 是其中 m=1 的特例。
- **未决问题**：需求输出未单列 метка，schema 尚需形式化。可将其保留为 признак 的 m=1 标记，
  或用派生视图显示；不得自行变成无关类型或凭检索次数断言唯一来源。
- **后续验证**：检查层级和输出语义，样例出现频率不能代替定义。依赖的完整群与严格 fits 尚未实现。
