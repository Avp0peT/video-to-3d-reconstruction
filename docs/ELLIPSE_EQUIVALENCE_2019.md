# 2019 椭圆代码的未知编号双射搜索

本增量实现 S-2019-CODES 打印58–59页定义中的未知编号双射搜索；没有完成整篇2019论文、退化椭圆域、分割或形象系统。主线首轮测试发现8点组合证书回读失败，专用codec修订尚待统一复测，见下文。无 CLI、UI 或旧合同改动。

## 原文核对与适用范围

本次实际查看存档 `outputs/delegation/KOZLOV_LEGACY/20261014_author_algorithms/sources/2019_codes_page2_audit.png` 和 `2019_codes_page3_audit.png`，并核对同目录 `2019_codes.txt`。

- 打印58页：三元组内部次序无关，分子与分母三元组不同；代码等价要求存在**同一个点标签双射**，使所有对应索引比例相等。原文的“平面图像”排除全部点落于一条直线或两条平行直线的情况。
- 打印59页引理1：非共线三点的最小外接椭圆面积是三角形面积的共同常数倍。因此椭圆面积比等于三角形面积比；此恒等式不需要浮点 π 或开方。
- 打印59页椭圆代码定义保留完整索引及同一编号双射。定理3的椭圆等价与仿射等价充要关系仅适用于作者的“平面图像”域。

输入每侧为完整 `dict[int64_label, (x,y)]`，3–8个不同二维点；坐标仅 int/Fraction，256位有理界；拒绝 bool、float、重复点。两侧可以同标签，也可以完全不同标签，属于各自命名空间。每个三元组均须非共线，沿用现有 `ellipse_code2019` 的严格域。三角形、平行四边形等不在作者平面定理域的输入仍可得到**定义级代码等价结果**；不会强行套用定理3。共线三元组不构造零面积正定椭圆，返回 UNSUPPORTED。

## API 与输出

`kozlov_lab.coding.ellipse_equivalence2019` 新增：

```python
search_ellipse_equivalence2019(source, target, *, max_work=2000000, seconds=30)
assess_ellipse_equivalence2019(source, target, certificate, *, max_work=2000000, seconds=30)
encode_ellipse_equivalence2019(certificate, *, max_work=2000000, seconds=30)
decode_ellipse_equivalence2019(envelope, *, max_work=2000000, seconds=30)
```

沿用 `_Budget`、`_Exhausted` 和已有精确椭圆代码构造/核验。所有嵌套调用消耗同一个剩余工作量/时间额度；构造、双射搜索及最终独立验算均计费。UNKNOWN 不带部分成功或部分负证书。较难的8点负例可能在默认额度内 UNKNOWN，不能据此断言不存在双射。

`status` 分别为 ELLIPSE_EQUIVALENT、NOT_ELLIPSE_EQUIVALENT、UNKNOWN、UNSUPPORTED。独立读回返回 VERIFIED、INVALID 或 UNKNOWN。另分开输出：

| 字段 | 含义 |
|---|---|
| `code_equivalent` | 作者定义的椭圆代码等价；未知/不支持为 None |
| `theorem_domain` | 两侧均满足作者排除单线/双平行线的平面域 |
| `theorem_conclusion` | 仅平面域中依据定理3输出仿射等价/不等价；域外 NOT_APPLICABLE |
| `affine_mapping_status` | 当前代码双射另有全点可逆仿射回代见证时 WITNESS_VERIFIED，否则 NOT_ESTABLISHED |

几何见证只检查本次找到的同一代码双射。NOT_ESTABLISHED 不否定其他双射下存在仿射映射。尤其正方形的所有三角形面积相同，可能先找到非仿射的编号置换；其代码等价可以为真、平面定理不适用、当前映射无仿射见证。不会用该映射失败覆盖代码定义结果。

## 完整搜索与独立证书

为避免证明域混用，本版**没有使用仿射锚三元组剪枝**，而是在同基数情况下按标签字典序枚举全部 n! 双射。上限8点意味着最多40320个候选；不同基数直接否定编号双射存在性。枚举、证书格式与预算属于项目对作者定义的实现选择，不是论文另行给出的搜索算法。

每个候选都保持整个编号关系，比较完整椭圆代码中的所有索引比值；遇到一个不等比值即可拒绝该候选。三点输入只有一个三元组，因此没有不同三元组对，其比例集为空；仍要求完整三点双射，不伪造自对比例。

**正证书**保存完整两侧椭圆代码（含逐三角形实际椭圆几何及最小性证书）、一个完整双射以及全部索引对比较账本 `(source_key, mapped_key, source_ratio, target_ratio)`。8点账本包含3080项。独立验证重新核两侧代码、输入绑定、双射完整性，遍历全部源索引，核映射索引及精确比例相等；不调用搜索器或比较账本构造器。

**负证书**同基数时保存每个候选排列及一个真正不等的索引比例反例，按最多256条分块存储。独立验证要求反例条数恰为 n!，按完整排列序逐条核验映射身份、覆盖、不重复、不遗漏和比例不等。每一允许双射均已被精确反例排除，才可否定定义级等价。不同基数时核验两侧完整输入及基数差，不需要排列反例。

这给出的证明是有限析取的完整裁决：存在一份全比例相等的同一双射即可成立；每一双射都有不等比例证据才可否定。预算中断不是有限析取已穷尽。

## 专用有界 JSON 封装

主线第一次真实测试发现：整个8点组合证书一次交给通用 `decode_exact` 会超过其20,000节点限制；该失败不改变数学结果，但阻止完整证书回读。保留通用限制，新增上述专用 encode/decode，完整8点测试继续保留56椭圆、3080比例和无损往返要求。

外层只允许 `schema/core/ratio_chunks/rejection_chunks` 四字段。core 精确保留证书除两个账本之外的所有字段，每个字段（尤其两侧完整椭圆代码）分别调用现有 exact codec。比例账本每256行分块，最多13块、合计最多3080行；负证书保留每256行分块，最多158块、合计最多40320行。每块继续使用原来20,000解码节点和32层深度限制，没有修改全局 JSON 限制。额外原始 JSON 预检每块最多200,000实际JSON节点（tag编码的包装节点也计入）、容器最多4096项、字符串最多4300字符；该预检不是放宽原codec的20,000语义节点限额。

原生结构遍历及JSON预检共同消费给定工作/时间预算；超限抛出既有 `_Exhausted`，不返回截断对象。非法结构、未知字段/缺失字段、超额块数/行数、浮点、bool混入标签或数值位置等抛出 ValueError。bool仅允许原证书规定的域标记位置。Fraction、tuple、None、标签和几何值保持原类型。JSON文本解析及重复对象键拒绝继续由调用方已有策略负责；decode 接受的是已经解析的对象。

**codec仅验证结构与精确表示，不执行数学核验，不输出 VERIFIED。** 即使结构正确，缺少反例或错误比例仍须交 `assess_ellipse_equivalence2019(source,target,decoded)` 检出；调用者不得将成功解析当作等价或穷尽证明。
