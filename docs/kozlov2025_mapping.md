## 1. изображение / часть / подизображение

- **Definition**：«**Изображением** называем конечное (непустое) множество точек на плоскости.»
  点是可"逼近"任意图形的；多点的集合与原图几乎不可区分；灰度/彩色可用点密度与三通道叠加表示。
  «**Частью** изображения A называем любое непустое подмножество B его точек.
  Любое изображение B′, аффинно эквивалентное изображению B, называем **подизображением** изображения A.»
  三维推广被明确提及：«Трехмерные изображения — точки в трехмерном евклидовом пространстве.»
  同页又说明后文讨论二维图像，并提及可推广到更高维。
- **Source**：PDF p.2（期刊 147），§2
- **Mathematical form**：`A = {a₁,…,aₙ} ⊂ R²`，`A ≠ ∅`；`B ⊆ A, B ≠ ∅`；`B′ ~ B`（аффинно）
- **Existing implementation**：`kozlov_lab.geometry.points.PointSet2D`（集合语义、重编号不变）；
  `kozlov_lab.stereo.model.PointSet3D`（R³ 版）
- **Status**：本节整体 `PARTIAL`。有限点集类型可复用；不能把这种基础复用记作 `часть` / `подизображение` / 三维结构全部 `EXACT`。
- **Engineering consequence**：复用现有点集与仿射关系工具。`подизображение` 是与某非空子集仿射等价的任意图像，
  原文并未把它直接定义成商集中的一个等价类；须显式保留子集、点身份与仿射等价关系。

## 2. среда S / S′ / S⋆

- **Definition**：«**Среда S** — произвольное изображение, состоящее из N (N ≥ 1) точек.
  Число частей среды — 2^N − 1. Множество частей (т.е. изображений) обозначим через **S′**.
  Образ из среды S будем трактовать как некоторую **группу изображений из S′** …
  Обозначим множество всех возможных групп через **S⋆**.»
- **Source**：PDF p.3（期刊 148），§2
- **Mathematical form**：`|Parts(S)| = 2^N − 1`；`S′ = P(S) \ {∅}`；`S⋆ = P(S′)`；
  任务定义为"把 S⋆ 压缩为可接受地称为 образа 的群组集合"
- **Existing implementation**：无
- **Status**：`MISSING`
- **Engineering consequence**：这是一个**组合爆炸**框架（`|S⋆| = 2^(2^N−1)`）。
  很小的 N 可作枚举 oracle；一般规模不能把全量枚举作为默认工程路径。
  给定候选群组的判定与有界搜索须标明搜索域、预算与完备性，不能把截断搜索当作完整结果。
  → 记入 `docs/open_questions.md` Q5。

## 3. отдельная группа（第一逼近）

- **Definition**：两图像 `непересекающиеся/отдельные` ⟺ 其**点编号集合**之交为空。
  群组内两两不相交 ⇒ **отдельная группа**；全体记 `S+` —— «это и есть первое сокращение множества S⋆».
  另定义 `кратные точки`：仿射变换后不同图像的点重合时，保留各自编号、按独立图像变换；
  并假定存在"逆变换恢复原环境 S"的操作。
- **Source**：PDF p.3–4（期刊 148–149），§3
- **Mathematical form**：`A ∩ B = ∅`（作用在编号集合 `M_A`, `M_B` 上）；`S+ ⊆ S⋆`
- **Existing implementation**：无（`coding/model.py` 的 `M_A` 是**编号集合**，语义可复用）
- **Status**：`MISSING`（但基础类型已存在）
- **Engineering consequence**：需要"编号集合"这一等公民 —— 现有 `coding/model.py` 已把
  `M_A` 建模为标签集合且**保留索引**，可直接作为 `отдельность` 判定的载体，无需再发明。

## 4. 中心与尺寸：最小面积外接椭圆

- **Definition**：«Дано изображение X. Обозначим через **W(X)** выпуклую оболочку для X.
  Известно [5], что для выпуклого множества W(X) существует **единственный наименьший по площади
  эллипс**, его вмещающий. **Центр этого эллипса** назовем **центром изображения X**, а длину
  большей оси — **размером** (для вырожденного случая, когда все точки из X расположены на прямой,
  эллипс с очевидностью превращается в отрезок прямой, центр — середина отрезка).»
  «Два изображения A и B называем **независимыми**, если W(A) и W(B) не имеют общих точек.»
- **Source**：PDF p.4（期刊 149），§4。引文 [5] = Загускин В.Л., «Об описанных и вписанных
  эллипсоидах экстремального объема», УМН 13:6 (1958) 89–93（PDF p.17 / 期刊 162）
- **Mathematical form**：`center(X) = center(argmin_{E ⊇ conv(X)} area(E))`；`size(X) = 长轴长`；
  退化：共线 ⇒ 椭圆退化为线段，中心 = 线段中点
- **Existing implementation**：新增 [`kozlov2025/ellipse.py`](../src/kozlov_lab/kozlov2025/ellipse.py) 的
  `minimum_enclosing_ellipse`，按[冻结数值契约](contracts_ellipse_v1.md)使用 NumPy float64 Khachiyan
  对偶更新求候选，再以 `Fraction` 对实际存储的世界坐标、中心、factor 和权重独立计算精确包含性与面积比证书。
  输入为 1–4096 个有限二维 binary64 兼容点；只去除精确重复点，精确共线/单点单独处理，近退化可明确数值失败。
- **Status**：`PARTIAL` / `TESTED_REAL_PARTIAL`（数值有限点域已测试，真实 SfM 特征点单例通过）。
  [pure02.xml](../outputs/delegation/ELLIPSE_2025/20261007T105441Z_main/pure02.xml) 保存 45 例、0 failure、
  0 error、0 skipped；[demo01](../outputs/delegation/ELLIPSE_2025/20261007T105441Z_main/DEMO_RESULT.json)
  唯一一次真实调用对 image 4 的全部 3571 个特征像素（3179 唯一点）返回 `APPROXIMATE_CERTIFIED`，
  独立 Fraction 重算确认全部原始点包含，面积比上界 `1.0049380785009892 ≤ 1.01`，来源未改。
- **Engineering consequence**：`APPROXIMATE_CERTIFIED` 只保证实际 binary64 输入的输出椭圆包含全部点，且
  `1 ≤ area(output)/area(optimum) ≤ 1 + area_tolerance`。它不是精确 Kozlov 中心，未给出中心坐标或长轴尺寸误差界，
  也不证明真实物体/图像测量精度；不得自动升级为严格 fits、覆盖或高层形象结论。未收敛/数值失败显式保留。
  用法、状态与证书字段见 [ELLIPSE_USAGE.md](ELLIPSE_USAGE.md)；本模块未新增 SciPy/OpenCV 依赖。
- **★ 定理支撑**：**Теорема 1**（PDF p.11 / 期刊 156）证明该中心在仿射变换下**协变**：
  «при аффинных преобразованиях изображения X … центр y изображения X переводится в центр y′»。
  证明用 `P(E)/P(X)` 最小性与唯一性。⇒ 这给出"中心"是仿射合法几何量的**理由**，
  不能只取质心/包围盒中心替代（质心不满足该定理所需的"最小面积"性质）。
- **验收边界**：已有用例覆盖全部点包含性、已知三角形/矩形/圆对称解的中心与面积、仿射中心/形状/面积协变、
  点/线/重复/近线输入、预算耗尽、非法输入、输出不可变与独立证书重算。有限用例不等于一般性定理证明，
  原文的精确中心协变性也不能直接当作浮点结果的精确性质。真实 demo 的对象仅为 SfM 特征像素集合，
  不代表物体 mask、图像边界或背景移除；真实物体中心/尺寸精度未评估。

## 5. покрытие / кусок / размер покрытия

- **Definition**：«Множество всех частей изображения X обозначим через X′. Рассматриваем
  **покрытие P_X** изображения X попарно независимыми частями из X′ (такое всегда есть).
  Части называем также **кусками** изображения X. **Размером покрытия** называем размер
  наибольшего куска в нём.»
- **Source**：PDF p.4（期刊 149），§4
- **Mathematical form**：`P_X = {X₁,…,X_m}`，`X_i ⊆ X`，`X_i` 两两 независимы（§4 定义），`∪X_i = X`；
  `size(P_X) = max_i size(X_i)`
- **Existing implementation**：无
- **Status**：`MISSING`
- **Engineering consequence**：需要独立部分的搜索/构造及完整覆盖检查；定义可明确而求解器尚缺，
  不能把尚未提取算法步骤直接记为原文定义有歧义。可先形式化独立性与覆盖契约。

- **Definition（严格版，§6）**：«Зададимся некоторым m из промежутка от 1 до n (n — число точек в A).
  Рассмотрим покрытие A′ изображения A **независимыми кусками** A₁,…,A_m … Центры кусков обозначим
  через a₁,…,a_m, в целом они составляют изображение **a+**, его называем **остовом (m-остовом)**.»
- **Definition（非正式版，§4）**：把图像分成若干 куски，使每个 кусок 的最小面积外接椭圆恰为**圆**
  且同半径，其圆心构成 остов；«Если в остове m точек, то его можно рассматривать как
  приближение **m-го уровня** … (соответственно называть **m-остовом**)»；
  ★ 该版明确是 **гипотеза / содержательное описание**，非形式定义。
- **Source**：严格版 PDF p.10（期刊 155）§6；非正式版 PDF p.5–6（期刊 150–151）§4
- **Mathematical form**：`O = {center(X_i)}_{i=1..m}`，`X_i` 为 независимые куски
- **Existing implementation**：无（`compression/official/kozlov_sketch.py` 实现的是 **2002** 的
  остов：r-覆盖 {A_r} 中点数最少者 —— **不同概念**）
- **Status**：`MISSING`；若将 `compression` 的 2002 实现直接当作 2025 实现则产生语义冲突，旧实现本身不因此错误。
- **Engineering consequence**：★ **必须**在代码里区分两种 остов：
  `S-2002` 的 r-остов（已有实现）与 `S-2025` 的 m-остов（待实现）。P4 已裁决保留旧公开 API，
  新增类型可用 `Ostov2025M`，不为统一名字大规模重命名旧模块。

## 7. футляр

- **Definition（первичный，§4/§6）**：«Такой набор кругов с центрами в точках остова называем
  также **футляром** (порождённым данным изображением).»
  «**Футляр изображения есть пара ⟨изображение A, остов O⟩**. Этой пары достаточно, чтобы по ней
  … построить систему кругов радиуса R с центрами в точках из O, определить границы-отрезки
  пересечения кругов (если пересечения есть), куски изображения A в каждом из кругов.»
  半径约束：«**ни один круг не включает центр другого круга** в качестве внутренней точки
  (т.е. максимальный радиус равен минимальному расстоянию между точками остова)»；
  「圆可相切甚至相交，但（截断）圆的**内点**只算交点连线之外较大的一侧」。
  «Если R меньше половины размера покрытия, то A′ называем **неправильным**.»
  只有 правильные покрытия 才用于 футляр。
  p.10 还明文要求每个块中的点距所属中心比距其他中心更近，块位于相应的截断圆域内；
  不得省略这些条件和此前的独立覆盖前提。
- **Definition（обобщённый，§7）**：«Пусть A — изображение … изображение O (далее называем его
  **остовом**) … дано некоторое число r не большее наименьшего расстояния между точками остова.
  Пусть для a_i ближайшая к ней точка из O **единственна** … Точку a_i называем **прилежащей** к o_j.
  Совокупность точек из A, прилежащих к o_j, называем **куском** … Пару ⟨A,O⟩ называем
  **футляром (n-футляром)**». 还要求每个点距其唯一最近中心**严格小于 r**、全部点归入块且各块非空。
  与 первичный 的区别：остов O、相对位置和受约束的 r 是给定的，不由 A 的块中心统一导出。
- **Source**：первичный PDF p.6–7（期刊 151–152）§4、PDF p.10（期刊 155）§6；
  обобщённый PDF p.13（期刊 158）§7
- **Mathematical form（primary，p.10）**：`F = ⟨A, O⟩`，`O = {center(A_i)}`，
  `R = min_{i≠j} ‖o_i − o_j‖`；`P_A` 为两两独立的覆盖，块须位于对应截断圆域，
  每个点到所属中心严格更近。原文 `R < size(P_A)/2 ⇒ неправильное`，不能改写为仅有
  `R ≥ size(P_A)/2` 就足以保证整个构造正确。
- **Mathematical form（generalized，p.13）**：给定 `O` 与 `r ≤ min_{i≠j} ‖o_i − o_j‖`；
  每个 `a ∈ A` 有唯一最近中心 `o_j`，满足 `‖a − o_j‖ < r`；全部点归入块，且各块非空。
  `r` 的上界含等号，点到中心的距离条件不含等号，两者不能混用。
- **Existing implementation**：无
- **Status**：`MISSING`
- **Engineering consequence**：P6 已选择按正式定义实现，须保留 primary 与 generalized 版本条件。
  primary 的 R 固定；generalized 的 r 是有原文约束的给定量，也不能随意替换为椭圆或任意可调区域。
  m=1 的最小点距、重复中心、primary 圆域边界相等、近中心比较的数值容差继续 `OPEN`；
  不擅填默认值或闭开边界规则。当前不另扩展可调工程区域。

## 8. вместимость / m-вместимое / вложимость

- **Definition**：«Расположим изображение b+ на изображении O **искомым образом** … Если при этом
  каждый кусок изображения B′ окажется внутри соответствующего круга (возможно, усечённого)
  футляра изображения A, то говорим, что данное **m-разбиение изображения B вместимо** в этот футляр.
  Изображение B называем **m-вместимым** в изображение A, если хотя бы одно из его m-разбиений
  вместимо в хотя бы один из m-футляров изображения A.»
- **Source**：PDF p.11（期刊 156）§6
- **Mathematical form**：`B m-вместимо в A` 要求存在合格分划与 футляр，使 §5 的 `искомое`
  互位下各变换后的块落入对应的圆域（有交叠时为截断圆域）；普通未截断圆盘包含测试不足。
- **Existing implementation**：无
- **Status**：`MISSING`
- **Engineering consequence**：★ 需求 brief 的 `fits(A, F) -> bool` 只对应其中的**存在性判定**，
  但它内部**依赖 §5 的"最优互位"**（不是任意仿射拟合）。若用"最小化重投影误差"代替，
  得到的是一个**不同的谓词**，必须标注为 `ENGINEERING_INTERPRETATION`。
  P7 已裁决：严格 API 不能证明稳定性时返回 `UNKNOWN` / `UNSUPPORTED` 及原因；数值失败不等于数学 False。
  近似优化单独命名，不得把其成功传递成严格 granularity / полная группа / эталон 已验证。

## 9. m-совместимая группа / дробность / эталон

- **Definition**：«Пусть группа G из S+ состоит из изображений A₁,…,A_k, и пусть u — наименьшее
  число точек в изображениях группы. Зададимся некоторым m из промежутка от 1 до u и пусть
  существует хотя бы одно из изображений группы такое, что **все A₁,…,A_k m-вместимы** в некоторый
  футляр этого изображения. Тогда группу называем **m-совместимой**. **Наибольшее значение m**,
  для которого группа m-совместима, обозначаем через **M** и называем **дробностью группы**.
  Те из изображений группы, **M-футляры которых вмещают все изображения группы**, называем её
  **эталонами**. Теперь каждая группа из S+ снабжена … дробностью, **набором эталонов**, и … M-футлярами на эталонах.»
- **Source**：PDF p.12（期刊 157）§6；含 эталон 概念的前置描述在 PDF p.8–9（期刊 153–154）§4
- **Mathematical form**：`M(G) = max { m ∈ [1,u] : G m-совместима }`；
  `эталоны(G) = { A ∈ G : M-футляр(A) 容纳全部 G }`（**集合，可为多个**）
- **Bounds（原文明文）**：`M ≥ 1`（任何群组都有）；所有图像仿射等价 ⇒ `M = 点数`；
  混入异类图像 ⇒ `M` 下降（原文举例：在"二"的群组里加入"四"）
- **Existing implementation**：无
- **Status**：`MISSING`
- **Engineering consequence**：P5 / P7 已裁决以下边界，求解器尚未完成：
  ① brief 的 `granularity(G) -> M` 与原文**方向一致**，但原文的 M 由 **m-совместимость**
  （存在性判定）决定，**不是**由"拟合误差阈值"决定 —— 阈值驱动的 M 是另一个量。
  ② 严格输出 эталон **集合**；工程/UI 所需单个代表另存 `selected_prototype` 与选择规则。
  不完整搜索只能给候选集及 `complete=false`；没有观测到多个 эталон 也不能改写集合定义。
  → `docs/open_questions.md` Q2。

## 10. полная группа / полный образ（第二逼近）

- **Definition**：«Пусть G₁ и G₂ — группы из S+ с одинаковой дробностью, и пусть множество
  изображений G₂ есть подмножество (собственное) группы G₁. Тогда говорим, что G₁ **полнее** G₂.
  Группу называем **полной**, если нет группы полнее, чем она.»
  «…в M′ могут быть вместимы и другие изображения среды. Назовём совокупность всех вместимых в M′
  изображений **максимальным наполнением** футляра M′ … максимальное наполнение футляра M′
  **есть полная группа**.» «Множество всех полных групп обозначаем через **S++** и трактуем как
  множество образов во втором приближении.»
- **Source**：PDF p.12–13（期刊 157–158）§7
- **Mathematical form**：`S++ = { G ∈ S+ : ¬∃G′ ⊋ G, M(G′)=M(G) }`；
  `G = 最大填充(M-футляр(эталон ∈ G))`
- **Existing implementation**：无
- **Status**：`MISSING`（★ 但这是最有工程价值的一条）
- **Engineering consequence**：第二逼近给出了构造 футляр 后进行识别的理论思路（p.12 原文解释：
  «он "выработал" футляр … позволит ему при появлении неизвестного изображения определить,
  вместимо оно в этот футляр или нет, то есть распознать изображение»）。
  可据此讨论候选识别路径；它不自动解决严格互位、完备搜索或数值判定问题，不能称为唯一入口或已可用实现。

## 11. непосредственный подобраз / спектр / существенная часть / замкнутый образ / шлейф / признак / метка

- **Definitions（原文）**：
  - «Такую максимальную подгруппу G′ называем **непосредственным подобразом** (по вложению)
    образа G. Набор всех непосредственных подобразов образа G называем **спектром** (по вложению).»
  - «Если группа Q **полная**, то образ Q называем **существенной частью** образа G,
    порождаемой частью o_{j1},…,o_{jh} остова O.»
  - «Образ Z, **не являющийся существенной частью никакого другого образа**, назовём **замкнутым**.»
  - «Совокупность всех групп, продолжаемых в данную замкнутую группу, называем её **шлейфом**.»
  - «Тогда часть Q называем **минимальной** или **признаком** образа G. … Частный случай признака,
    когда m равно единице, называем **меткой** образа G.»
- **Source**：подобраз/спектр PDF p.14（期刊 159）；существенная часть PDF p.14（159）；
  замкнутый/перекресток PDF p.15（160）；шлейф/признак/метка PDF p.16（161）
- **Mathematical form**：`M` 由 часть остова `O_{j1..jh}` 生成的群组；`Q полная ⇒ Q = существенная часть`；
  `признак = 极小生成集`（任何真子集不生成 существенная часть）；`метка = признак with m = 1`
- **Existing implementation**：无
- **Status**：`MISSING`
- **Engineering consequence**：可把这些概念作为 `ObjectModel{parts, features}` 的候选工程映射，
  但字段名相似不证明语义一一对应。`существенная часть` / `признак` / `метка` 须分别满足原文的
  完整性、极小性及 m=1 条件；普通 Part / feature / 单点特征不能自行获得这些理论身份。
  ✓ 但 brief 未提"перекресток""шлейф""спектр"，这些是论文里**有定义**但 brief 无需求的量 —— 记录不扩展。
- **★ Теорема 2（可作实现依据）**：PDF p.15–16（期刊 160–161）。
  若 `V₁ = существенная часть G`，`O₁ ⊂ O₃ ⊂ O`，则 `O₃` 生成的 `V₃` **也是** существенная часть G。
  ⇒ **存在性可沿 остов 单调扩张**，这给"增量构造 существенная часть"提供合法性基础。

## 12. 适用范围与引用边界

- S-2025 PDF p.2 / 期刊 147 明确提及三维图像与高维推广，后文详细展开二维结构；
  没有给出本项目完整三维实现及真实照片重建流程。可引用其明确陈述，新增三维定义仍标 `OUR_3D_EXTENSION`。

- `эскиз` / `фрагмент` 等词的检索计数只帮助定位，不能证明两篇理论不重叠或不存在同类概念。
